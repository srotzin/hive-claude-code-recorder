# Two real Claude Code sessions, matched against the vendor's own delivery log

Recorded October 11, 2026 with Claude Code and plugin 1.4.0, in service mode, against two local MCP stand-ins (`market-data-standin.mjs`, `ref-data-standin.mjs`) that keep a signed delivery log with `vendor-kit/delivery-log.mjs`. Every value the stand-ins return is made up, and every reply says so.

- `session-1.jsonl`: Claude pulls Brent, 5 mortgage rows (outside the market-data entitlement) and one issuer record, then answers (`answer-1.txt`).
- `session-2.jsonl`: Claude pulls WTI.
- After the two sessions, one pull of 5 mortgage rows went straight to the market-data stand-in, outside Claude Code and its recorder. That is the pull a firm-side record alone can never show.
- `vendor/market-data.deliveries.jsonl`: the vendor's signed log, 4 deliveries, each witnessed before it went out. `vendor/market-data.delivered-bodies.jsonl` is what the vendor kept of each delivery. In use, only the vendor holds it.
- `copies/`: market-data's copy of each session, and `match.market-data.json`, signed by the stand-in vendor key and accepted by the firm's recorder key: 3 pulls matched, 1 delivered with no record, 0 recorded with no delivery.

From the vendor's kept body, the answer's total ($1,260,000) and average ($252,000) trace to the sum and the average of the 5 balances in delivery 1.

`node tests/delivery-tamper.mjs <vendor-key.pem>` checks all of it against the live witness at witness.thehiveryiq.com and writes 9 rewrites to `tamper/` with `MANIFEST.json`. All 9 are rejected. The stand-in vendor key was generated by Hive and is not in the repository, and Hive ran the witness, so this run is not independent.
